# My-Cafe — Project Specification

## 1. Project Purpose

My-Cafe is a fictional café and coffee shop website based in Kandy, Sri Lanka.

The website is being recreated as a simple, modern, search-visibility-ready website inspired by the general structure of a small café website.

The goal is not to copy an existing business website.

The goal is to create an original website with strong:

- SEO — Search Engine Optimization
- AEO — Answer Engine Optimization
- GEO — Generative Engine Optimization
- AISO — AI Search Optimization

The website must remain simple, maintainable, accessible, performant, and useful to real users.

---

## 2. Important Constraint

My-Cafe is a fictional business created for this project.

Do NOT use:

- The original reference website's business name
- Original business address
- Original phone number
- Original email
- Original logo
- Original images
- Original testimonials
- Original reviews
- Original ratings
- Original awards
- Original credentials
- Original business claims
- Original copyrighted content

The reference website is used only for general inspiration and audit purposes.

All My-Cafe content and business information must be original.

# 6. Website Goals

The website should help users:

1. Understand what My-Cafe is.
2. Understand what My-Cafe offers.
3. Explore the menu.
4. Understand where the café is located.
5. Find opening hours.
6. Contact the café.
7. Discover useful café-related content.
8. Decide whether My-Cafe is relevant to their needs.

Primary conversion actions:

- Explore menu
- Visit the café

# 11. AEO Requirements

The website should make useful answers easy to find and extract.

Use the pattern where appropriate:

Question / user need
→ direct answer
→ supporting information

Examples of useful questions:

- What is My-Cafe?
- Where is My-Cafe located?
- What does My-Cafe serve?
- What coffee is available?
- What are the opening hours?
- How can I contact My-Cafe?

Important information must exist as accessible HTML text.

Do not hide important information inside images, canvas elements, or inaccessible interactions.

FAQ content must be genuinely useful.

Do not create fake or keyword-focused FAQs.

# 13. AISO Requirements

The website should be easy for AI-powered search systems to understand.

Important information should be:

- Visible
- Semantic
- Structured
- Consistent
- Machine-readable
- Easy to extract

Clearly communicate:

- What My-Cafe is
- Where it is
- What it offers
- Who it serves
- How users can visit
- How users can contact it

Use meaningful headings, paragraphs, lists, tables, descriptive links, semantic HTML, metadata, and structured data.

Do not add artificial "AI keywords" or undocumented AI-specific markup.

---

# 14. Structured Data

Use JSON-LD where appropriate.

Potential structured data types include:

- LocalBusiness / appropriate business type
- WebSite
- WebPage
- BreadcrumbList
- Article
- Organization where appropriate

Structured data must:

- Represent real project information
- Match visible website content
- Use valid Schema.org structure
- Avoid fabricated values
- Avoid fake reviews or ratings
- Avoid unnecessary schema

Valid structured data does not guarantee search rankings or AI visibility.

---

# 15. Internal Linking

Important pages must be reachable through normal crawlable links.

Use meaningful anchor text.

Examples:

- Explore our menu
- Visit My-Cafe in Kandy
- Read our coffee guide
- Learn more about My-Cafe

Avoid generic links such as "click here" when a descriptive link is possible.

Connect related content naturally.

---

# 16. Accessibility

Accessibility is a core requirement.

Use:

- Semantic HTML
- Proper headings
- Keyboard-accessible controls
- Visible focus states
- Accessible form labels
- Meaningful alt text
- Appropriate color contrast
- Native HTML controls where possible

Use buttons for actions.

Use links for navigation.

Do not use clickable divs/spans when a native element is appropriate.

Do not use ARIA as a replacement for proper HTML.

---

# 17. Performance

The website should remain lightweight.

Priorities:

- Optimized images
- Appropriate image dimensions
- Modern image formats where practical
- Lazy loading for non-critical images
- Efficient rendering
- Minimal JavaScript
- Minimal dependencies
- Avoid unnecessary animations
- Avoid unnecessary network requests

Do not optimize blindly.

Prefer simple solutions and measure actual problems.

---

# 18. React Architecture

Use:

- Functional React components
- TypeScript
- Small focused components
- Semantic HTML
- Clear data flow

Do not create excessive component abstractions.

Do not introduce global state unless a real requirement exists.

Do not create large numbers of folders/components without a clear purpose.

Keep content/data separate from presentation when that improves maintainability.

---

# 19. Rendering / Indexability

Important public content must be accessible to search engines and users without unnecessary dependence on client-side JavaScript.

Choose the simplest rendering architecture that provides good indexability and performance.

Do not introduce SSR/SSG or another rendering framework without first evaluating whether it is actually required for this project.

The implementation must preserve:

- Crawlability
- Indexability
- Metadata
- Accessible content
- Fast initial rendering
